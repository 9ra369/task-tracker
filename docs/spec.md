# タスク管理ツール 仕様書（v0.6 ドラフト）

> v0.2 での変更点: デフォルトタブの固定化、開始日／目標日の導入、リンクのラベル付き管理、カード面へのメモ表示、複数ユーザー対応のオン/オフ設定、File メニューへの入出力の集約、検索フィルタ、Shift 複数選択、カレンダーUIによる日付選択、ブランドマークの改善。
>
> v0.3 での変更点: カード詳細を画面中央のモーダルに変更、複数選択の解除を「何もないところをクリック」に変更（カードクリックは常に詳細を開く）、モーダルからのタブ（ステータス）移動、並び順（作成日時順／手動並び替え）の切り替え、タブ内グループ（同一プロジェクトの束ね）、カードへのタグ付けとタグフィルタ。
>
> v0.4 での変更点: タイトルバーに File の左隣として **Setting メニュー**を新設し、グループ機能・タグ機能のオン/オフをチェックボックスで切り替え可能に。同メニューの **Theme** からライト／ダークテーマを切り替え可能に（既定はダーク）。
>
> v0.5 での変更点: 表示名（自分の名前）をいつでも変更できるように。歯車アイコンの「設定」モーダルを廃止し、複数ユーザー対応・表示名・保存先もすべて **Setting メニュー**に統合。File の左隣に **Edit メニュー**を新設し、元に戻す（Undo・Ctrl+Z）／やり直す（Redo・Ctrl+Shift+Z）を追加。
>
> v0.6 での変更点: 各タブの**上端の枠線だけに色を付けられる**ように（タブ本体やヘッダー背景は着色しない）。列ヘッダーの小さな丸ボタンから8色のプリセット、または「枠線の色を解除」を選択できる。詳細は各節を参照。

## 1. 概要

Electron 製のデスクトップアプリとして、個人〜小規模チーム向けの汎用タスク管理ツールを開発する。

参考にしたのは社内の `shot_tracker`（ショット進行管理ツール）。ショット番号・工程（レンダリング待ち／FB待ち／作業中…）をカンバン形式の列で管理する構成を、ショット制作に限らない一般的なタスク管理に一般化する。

最大の違いは「列（タブ）を固定のワークフローとして持つのではなく、ユーザーが自由に追加・削除・並び替えできる」点。プロジェクトごとに工程や状態の呼び方が変わっても、テンプレートを作り直す必要がない。

## 2. 背景

- `shot_tracker` は「レンダリング待ち → FB待ち → FB転送済 → マスク出力待ち → 作業中 → FB済み・修正あり → パブリッシュ待ち → 完了」という、ショット制作パイプライン特有の列構成を持つ。
- 列の名前・数はプロジェクトによって異なり、ハードコードされたステータスでは使い回せない。
- 同じ「カード×列」のカンバン構造は、ショット以外の一般的なタスク管理（開発タスク、事務作業、個人のTODOなど）にもそのまま転用できる。
- → 列（タブ）をユーザー定義にした汎用版を作る。

## 3. 目的・ゴール

1. ユーザーが自分の作業フローに合わせて列（タブ）を自由に作れること。
2. 各列にタスクカードを追加し、進捗に応じて列間を移動できること。
3. `shot_tracker` 同等の情報密度（担当者・メモ・関連ファイルへのリンク・件数バッジなど）をタスクにも持たせられること。
4. ローカル環境で完結し、データはファイルとして手元に残ること（サーバー不要）。

## 4. 想定ユーザー

- 個人で複数プロジェクトの進行を管理したいクリエイター／エンジニア。
- 少人数チームで、Trello/Notion のような重量級ツールを導入するほどではない進行管理をしたいチーム。

## 5. 主要機能一覧

### 5.1 タブ（列）管理

デフォルトのタブは「未着手 / 進行中 / 最終確認 / 完了」の 4 つ。このうち **未着手（先頭）と完了（末尾）は固定タブ**とし、削除・並び替えの対象外にする（列ヘッダーに 🔒 を表示）。ワークフローの入口と出口を固定することで、どのボードでも「まだ手をつけていないもの」と「終わったもの」が必ず同じ位置に来るようにする。それ以外のタブ（進行中・最終確認・ユーザーが追加したタブ）は自由に追加・削除・並び替えができる。

| 機能 | 内容 |
|---|---|
| タブの追加 | ボード右端の「＋ 新しいタブを追加」から作成。新規タブは常に固定タブ「完了」の直前に挿入される。 |
| タブの削除 | 列ヘッダーの × から削除（カードが残っている場合は確認ダイアログ）。固定タブは削除不可。 |
| タブの並び替え | 列ヘッダーをドラッグして並び替え（固定タブの前後には移動不可）。 |
| タブの名称変更 | 列名をダブルクリックしてインライン編集（固定タブも名称のみ変更可）。 |
| 件数バッジ | 列ヘッダーに、その列に属するカード数を表示（`shot_tracker` と同様）。 |
| 空列表示 | カードが 0 件の列は `- empty -` を表示。 |
| タブの色分け | 列ヘッダー左の小さな丸ボタンから、タブの**上端の枠線だけ**に色を付けられる。タブ本体やヘッダーの背景は着色しない（あくまで一目で見分けるための線）。8色のプリセットから選ぶか、「枠線の色を解除」で既定の色に戻す。色は固定タブにも設定できる（固定はタブの位置・削除可否の話であり、色分けとは独立）。 |

### 5.2 タスクカード管理

| 機能 | 内容 |
|---|---|
| カードの追加 | 列下部の「＋ タスクを追加」、またはグループ内の「＋ タスクを追加」から作成。タイトルは必須、他は任意。 |
| カードの編集 | カードクリックで詳細モーダル（**画面中央に表示**）を開き、各項目を編集。Shift を押しながらのクリックは編集ではなく複数選択になる（5.7参照）。 |
| カードの削除 | モーダル内の「タスクを削除」から削除（確認あり）。 |
| ステータス（タブ）の変更 | ドラッグ＆ドロップに加えて、詳細モーダルの「ステータス」セレクトからも変更できる。選択したステータスに応じて「グループ」セレクトの候補が切り替わる。 |
| カードの項目 | タイトル / ステータス（列） / グループ / 優先度 / 開始日 / 目標日 / 担当者（複数ユーザー対応時のみ） / タグ / メモ / リンク（複数可） |
| 優先度表示 | 色付きドットで表現（赤＝高、黄＝中、緑＝低）。`shot_tracker` の作業者コメントの色分けに相当。 |
| メモのカード面表示 | メモは詳細モーダルだけでなく、カード面にも 2 行までのプレビューを表示し、開かなくても内容を確認できるようにする。 |
| 開始日・目標日 | いつ着手し、いつまでに終える予定かをカードに持たせる。両方設定されている場合、カードに「今日がどのあたりか」を示す進捗バーを表示する。目標日を過ぎても未完了（完了タブに入っていない）の場合は赤字で強調する。 |
| リンク | 詳細モーダルの「＋ リンクを追加」で 1 件ずつ追加。各リンクは `表示名（ラベル）` と `URL／ファイルパス` の組で管理し、ラベルは後から自由に変更できる。カード面にはラベル付きのチップとして表示され、クリックすると開く（http/https は既定のブラウザで開き、ローカルパスは Electron 版で OS の既定アプリ・File Explorer に委譲する。Web版プロトタイプではローカルパスは開けない旨をトーストで案内）。 |
| タグ | 詳細モーダルのタグ欄にテキストを入力して Enter（または `,`）で追加するチップ入力。カード面にも `#タグ名` の形で表示し、5.3 のフィルタで絞り込める。 |

### 5.3 検索・フィルタ

- 上部の検索ボックスでタスクタイトルを横断検索。
- 検索ボックスの右の「フィルター」から、優先度（複数選択）・目標日の範囲（開始/終了）・タグ（複数選択、ボード内に実在するタグのみ表示）で絞り込み。複数ユーザー対応がオンの場合のみ担当者フィルタも表示。
- 有効なフィルタ数をボタン上のバッジで表示し、「クリア」で一括解除。

### 5.3.1 並び順

- ツールバーの「並び順」で、列内のカード表示順を **作成日時順**（既定）と **手動並び替え** から選べる。
- 手動並び替え時のみ、カードをドラッグして列内の任意の位置に並べ替えられる（ドロップ先カードの上半分/下半分で前後どちらに入るかを判定）。作成日時順の間は並び替えの手動操作は無効。

### 5.4 日付選択（カレンダーUI）

- 開始日・目標日、フィルタの日付範囲はすべて、ネイティブの `<input type=date>` ではなく、テーマに合わせたカスタムのカレンダーポップオーバーで選択する。月送り・「今日」・「クリア」を備える。

### 5.5 File メニュー・データ保存

- 画面左上の「File」メニューに、JSON のエクスポート／インポート、サンプルデータへのリセットを集約する（ヘッダー上には常設ボタンを置かない）。
- 保存先パスの指定は 5.10 の Setting メニューに統合されている（Electron 版ではネイティブのフォルダ選択ダイアログを想定。Web版プロトタイプではパス文字列の保持のみで、実際のファイル書き込みは行わない）。
- エクスポートで現在のボード状態（タブ構成・カード・設定）を JSON 出力し、インポートで復元できる。インポート・サンプルデータへのリセットを行うと、5.14 の Undo／Redo 履歴はクリアされる（読み込んだデータより前の状態には戻せない）。

### 5.6 複数ユーザー対応・表示名（拡張性のための設定）

- 表示名（自分の名前）は 5.10 の Setting メニューからいつでも変更できる。複数ユーザー対応のオン/オフに関わらず常に編集可能。
- 現状は個人利用が前提だが、将来チームで使うことを見込み、Setting メニューに **複数ユーザー対応を有効にする** チェックボックスを設ける。
- **デフォルトはオフ**。オフの間は担当者の入力欄・カード上の担当者表示・検索の担当者フィルタ・タイトルバーのユーザー表示をすべて非表示にし、個人のタスク管理に画面をシンプルに保つ（表示名自体は裏で保持され続ける）。
- オンにすると、タイトルバーのユーザー表示・カードへの担当者アサイン・担当者フィルタが有効になる。メンバー管理や権限などのチーム機能そのものは引き続き将来検討（5.13 参照）。

### 5.7 複数選択・一括操作

- カードを Shift を押しながらクリックすると、詳細モーダルを開かずに複数選択できる（トグル式）。
- 1 件以上選択すると画面下部に一括操作バーが表示され、「選択した件数」「移動先タブの選択」「削除」「選択解除」ができる。
- 通常クリック（Shift なし）は、選択の有無にかかわらず常にそのカードの詳細モーダルを開く。
- 選択の解除は、カード以外の「何もないところ」（ボードの余白・列の背景など）をクリックしたときに行う。誤って別カードをクリックしても詳細が開くだけで選択状態を壊さない一方、明確に空所をクリックすれば一括解除できる。

### 5.8 タブ内グループ

- 同じステータス（タブ）の中に、プロジェクト単位などでまとめる**グループ**を作成できる。列下部の「＋ グループを追加」で作成し、グループ名はダブルクリックで変更可能。
- グループがまだ 1 つも無い列は従来どおりのフラットなカード一覧として表示され、グループを作った列だけがグループ見出し付きの区切り表示になる（既存の使い方を崩さない）。
- グループに属さないカードは「未分類」として同じ列内にまとめて表示される。
- カードのグループ所属は、詳細モーダルの「グループ」セレクト、またはカードをグループの一覧へドラッグ＆ドロップすることで変更できる。
- グループを削除すると、そのグループに属していたカードは削除されず「未分類」に戻る（確認ダイアログあり）。グループは列（タブ）をまたがない（列ごとに個別のグループ集合を持つ）。
- 5.10 の Setting メニューで機能自体をオフにできる。オフの間もデータ（`groups` / `groupId`）は保持され、再度オンにすれば元の状態で復元される。

### 5.9 タグ・タグフィルタ

- カードに複数のタグを付けられる（詳細モーダルでチップ入力）。カード面には `#タグ名` として表示。
- 検索フィルタの「タグ」セクションで、ボード内に実在するタグをチップとして一覧表示し、選択したタグのいずれかを含むカードだけに絞り込める（OR条件）。
- 5.10 の Setting メニューで機能自体をオフにできる。オフの間もカードの `tags` データは保持され、表示・入力欄が隠れるだけ。

### 5.10 Setting メニュー（アプリ全体の設定を集約）

タイトルバーの **File の左隣**に、独立した「Setting」メニュー（プルダウン）を置く。旧バージョンにあった歯車アイコンの「設定」モーダルは廃止し、アプリ全体に関わる設定はすべてこの Setting メニュー1か所に集約する。

| セクション | 項目 | 内容 |
|---|---|---|
| 表示 | グループ機能を有効にする | チェックボックス。オフにするとタブ内グループ（5.8）の UI が隠れ、列はすべてフラットなカード一覧になる。既定はオン。 |
| 表示 | タグ機能を有効にする | チェックボックス。オフにするとタグ入力・カード上のタグ表示・タグフィルタが隠れる。既定はオン。 |
| Theme | Black / White | テキストのみの 2 択ボタン（アイコンなし）。クリックした時点で即座に切り替わる。既定は Black（ダーク）。 |
| ユーザー | 表示名 | テキスト入力。自分の名前をいつでも変更できる（5.6）。 |
| ユーザー | 複数ユーザー対応を有効にする | チェックボックス（5.6）。 |
| 保存先 | 保存先パス + 参照... | テキスト入力とフォルダ選択（Electron版でネイティブダイアログを想定）。 |

いずれの項目も操作した時点で即時反映・即時保存され、メニュー自体はチェックや入力のたびに閉じない（外側クリックで閉じる）。

### 5.11 テーマ（ライト／ダーク）

- アクセントカラー（アンバー）・タイポグラフィ・レイアウトはそのままに、背景・境界線・文字色・影の濃さだけをライト用トークンに差し替える。単純な白黒反転ではなく、ダーク側と同じ「面が奥から手前に向かって明るくなる」階調構造（ページ < パネル < カード < チップ）をライト側でも保つ。
- 優先度ドットやリンクの色（成功・警告・危険・リンク）は、白背景でも視認できるようライト用に個別調整する。
- テーマ設定は `settings.theme` に保存され、次回起動時も維持される。

### 5.12 Edit メニュー（Undo / Redo）

タイトルバーの **File の左隣・Setting の右隣**に「Edit」メニューを置く。

| 項目 | ショートカット | 内容 |
|---|---|---|
| 元に戻す（Undo） | `Ctrl+Z` | 直前のボード編集（カード・タブ・グループの追加/編集/削除/移動、並び替えなど）を1手戻す。 |
| やり直す（Redo） | `Ctrl+Shift+Z` | Undo で戻した操作をやり直す。新しい編集を行うと Redo 履歴は破棄される。 |

- Undo/Redo の対象は**ボードの内容（タブ・グループ・カード）の編集**に限る。Theme やグループ/タグ機能の有効・無効、複数ユーザー対応、表示名、保存先といった「アプリの設定」は対象外（意図せず設定が巻き戻る混乱を避けるため）。
- 戻せる操作が無い場合は Undo、やり直せる操作が無い場合は Redo が淡色表示（無効化）になる。
- JSON インポートやサンプルデータへのリセットを行うと履歴はクリアされる（5.5）。

### 5.13 チーム／担当者管理（将来検討）

- メンバー一覧の管理、複数ユーザー対応時のアサイン候補の入力補助など。
- `shot_tracker` の「チーム管理」相当。v0.5 でも対象外（5.6 の設定でオン/オフの土台のみ用意）。

### 5.14 通知連携（将来検討）

- Discord Webhook などへの通知連携。`shot_tracker` の「FBを受け取る」「Discord」ボタンに相当。v0.5 では対象外。

## 6. 画面構成（UI構成）

```
┌───────────────────────────────────────────────────────────────────┐
│ [Setting▾] [Edit▾] [File▾]                        (ユーザー名)     │ ← メニューバー行
│           ⧄⧄ task_tracker   タスク進行管理                         │ ← ソフト名行（メニューの下）
├───────────────────────────────────────────────────────────────────┤
│ [ 🔍 検索... ]     [フィルター▾]     並び順:[作成日時順▾]   全 N 件  │ ← ツールバー
├───────────────────────────────────────────────────────────────────┤
│ 🔒未着手(3)   進行中(7)          最終確認(2)   🔒完了(12) [＋タブ追加]│ ← 列ヘッダー行
│ ┌────────┐ ┌ プロジェクトA ┐ ┌────────┐ ┌────────┐                 │
│ │ カード  │ │  カード       │ │ カード  │ │ カード  │                 │
│ │[+追加]  │ │  カード       │ │[+追加]  │ │[+追加]  │                 │
│ │[+グループ]│ ┌ 未分類 ┐    │ │[+追加]  │ │[+追加]  │                 │
│ └────────┘ │  カード       │ └────────┘ └────────┘                 │
│             │[+追加]        │                                       │
│             └───────────────┘                                       │
└───────────────────────────────────────────────────────────────────┘

        カードクリック → 画面中央にモーダル表示（ステータス／グループ／
        優先度／開始日・目標日／担当者／タグ／リンク／メモ）
```

- `shot_tracker` のダークテーマ・密度の高いカード表示を踏襲しつつ、列数・列名（固定タブを除く）は完全にユーザー定義。
- ブランドマーク（旧: プレーンな `//`）は、アクセントカラーのグラデーションを効かせた小さな斜線ロゴに変更し、タイムコード／スラッシュ表記のモチーフを残しつつ質感を上げる。
- ヘッダーには常時表示のバッジ（旧「ローカル保存」表示）は置かない。ユーザー表示は複数ユーザー対応がオンの時だけ右端に出る。
- タイトルバーは2段構成。上段にメニューバー（Setting / Edit / File とユーザー表示）、下段にソフト名（ブランド）を配置する。
- カードにはタイトル・優先度・タグ・メモのプレビュー・開始日/目標日・リンクチップを表示し、詳細はクリックで画面中央のモーダルとして展開（Shift+クリックは複数選択、選択解除は空所クリック）。
- 列内にグループを作ると、列の中に「プロジェクトA」「未分類」のような区切りが表示される（5.8）。
- 「Setting」メニューでグループ・タグ機能のオン/オフ、Theme（Black/White）、表示名、複数ユーザー対応、保存先をすべて設定できる（5.10）。歯車アイコンの設定ボタンは廃止。
- 「Edit」メニューで Undo（Ctrl+Z）／Redo（Ctrl+Shift+Z）ができる（5.12）。

## 7. データモデル（JSON構造案）

```jsonc
{
  "settings": {
    "multiUser": false,          // 複数ユーザー対応のオン/オフ（既定: false）
    "currentUser": "泉谷",        // 表示名（multiUser時のみ使用）
    "savePath": "",               // 保存先パス（Electron版でファイル書き込み先として使用）
    "sortMode": "created",        // "created"（作成日時順） | "manual"（手動並び替え）
    "groupsEnabled": true,        // タブ内グループ機能のオン/オフ（既定: true）
    "tagsEnabled": true,          // タグ機能のオン/オフ（既定: true）
    "theme": "dark"                // "dark" | "light"（既定: dark）
  },
  "columns": [
    {
      "id": "col-002",
      "name": "進行中",
      "order": 1,
      "fixed": null,               // "start" | "end" | null（固定タブかどうか）
      "color": "#3b82f6",          // タブ上端の枠線色（8色プリセットの16進値）。null で既定色
      "groups": [                  // このタブの中だけで有効なグループ（プロジェクト単位の束ね）
        { "id": "grp-001", "name": "プロジェクトA", "order": 0 }
      ],
      "cards": [
        {
          "id": "card-001",
          "title": "仕様書のレビュー",
          "assignee": "泉谷",        // multiUser時のみ表示・編集
          "priority": "high",        // high | mid | low
          "startDate": "2026-08-01", // 開始日（任意）
          "dueDate": "2026-08-05",   // 目標日（任意）
          "tags": ["ドキュメント", "急ぎ"],
          "memo": "コメント欄",
          "links": [
            { "id": "lnk-001", "label": "素材フォルダ", "url": "Z:/Projects/.../spec_v001.docx" }
          ],
          "groupId": "grp-001",      // 所属グループ（null なら未分類）
          "createdAt": "2026-08-01T09:00:00+09:00"
        }
      ]
    }
  ]
}
```

- 1 ファイル 1 ボードを基本とし、複数プロジェクトは複数ファイルで管理する（`shot_tracker` のサーバーパス切り替えに相当）。保存先は `settings.savePath` で指定する。
- `columns[].fixed` により、未着手（`"start"`）・完了（`"end"`）を先頭・末尾に固定する。中間タブはすべて `fixed: null`。
- `columns[].color` はタブ上端の枠線色のみに使う（`{f43f5e, f97316, eab308, 22c55e, 14b8a6, 3b82f6, a855f7, ec4899}` の8色プリセットから選択、または `null`）。タブの背景やヘッダーの塗りつぶしには使わない。
- `links` は文字列配列ではなく `{id, label, url}` のオブジェクト配列とし、表示名を独立して編集・変更できるようにする。
- `columns[].groups` は列（タブ）ごとに独立して持つ。カードの `groupId` はその列の `groups[].id` を参照し、列をまたいで移動した場合は `null`（未分類）にリセットする。
- `settings.sortMode` が `"manual"` の間は、`cards` 配列内の並び順そのものが表示順として扱われる（ドラッグ操作は配列の並び替えとして永続化される）。`"created"` のときは表示時に `createdAt` でソートし、配列順は変更しない。
- 将来的に複数ボードをタブで切り替えられるようにする拡張余地を残す。

## 8. 技術スタック（案）

| レイヤー | 候補 |
|---|---|
| ランタイム | Electron |
| UI | HTML/CSS + Vanilla JS、または React（規模次第で判断） |
| データ永続化 | ローカル JSON ファイル（`fs` 経由）。将来的に SQLite も検討 |
| ドラッグ＆ドロップ | HTML5 Drag and Drop API、または `SortableJS` |

v0.1 のプロトタイプでは依存を増やさず、Vanilla JS + localStorage で UI 検証を行う（本リポジトリの `prototype/index.html` を参照）。

## 9. 非機能要件

- オフラインで完結すること（外部サーバー通信は必須にしない）。
- カード枚数が数百件になっても列のスクロールが破綻しないこと。
- ダークテーマを既定とする（`shot_tracker` の視認性の高さを踏襲）。
