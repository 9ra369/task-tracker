# タスク管理ツール 仕様書（v0.10 ドラフト）

## 1. 概要

Electron 製のデスクトップアプリとして、個人〜小規模チーム向けの汎用タスク管理ツールを開発する。

参考にしたのは社内の `shot_tracker`（ショット進行管理ツール）。ショット番号・工程（レンダリング待ち／FB待ち／作業中…）をカンバン形式の列で管理する構成を、ショット制作に限らない一般的なタスク管理に一般化する。

最大の違いは「列（タブ）を固定のワークフローとして持つのではなく、ユーザーが自由に追加・削除・並び替えできる」点。プロジェクトごとに工程や状態の呼び方が変わっても、テンプレートを作り直す必要がない。

v0.10 は、v0.9 に対する改善提案書のレビューを反映した版。仕様として未定義だった挙動（タブ削除時のカードの行き先、Undo の対象範囲、並び順の二重管理など）を確定し、データ保護（アトミックな保存、バックアップの世代設計）とセキュリティ（Markdown レンダリングのエスケープ、リンクを開く際の検証）の方針を明記した。変更点の一覧は [付録A. 変更履歴](#付録a-変更履歴) を参照。

## 2. 背景

- `shot_tracker` は「レンダリング待ち → FB待ち → FB転送済 → マスク出力待ち → 作業中 → FB済み・修正あり → パブリッシュ待ち → 完了」という、ショット制作パイプライン特有の列構成を持つ。
- 列の名前・数はプロジェクトによって異なり、ハードコードされたステータスでは使い回せない。
- 同じ「カード×列」のカンバン構造は、ショット以外の一般的なタスク管理（開発タスク、事務作業、個人のTODOなど）にもそのまま転用できる。
- → 列（タブ）をユーザー定義にした汎用版を作る。

## 3. 目的・ゴール

1. ユーザーが自分の作業フローに合わせて列（タブ）を自由に作れること。
2. 各列にタスクカードを追加し、進捗に応じて列間を移動できること。
3. `shot_tracker` 同等の情報密度（担当者・メモ・関連ファイルへのリンク・件数バッジなど）をタスクにも持たせられること。
4. ローカル環境で完結し、データはファイルとして手元に残ること（サーバー不要）。

## 4. 想定ユーザー

- 個人で複数プロジェクトの進行を管理したいクリエイター／エンジニア。
- 少人数チームで、Trello/Notion のような重量級ツールを導入するほどではない進行管理をしたいチーム。

## 5. 用語定義

同じ概念が画面上のラベル・本文・データモデルで異なる呼び方をされている箇所があるため、対応表を以下に固定する。実装者との会話や Issue 起票では、できる限りこの表の「正式名」を使う。

| 正式名（本仕様書での呼称） | UI 上のラベル | データモデル上の表現 | 補足 |
|---|---|---|---|
| 列（タブ） | 「タブ」（列ヘッダー行）／「ステータス」（カード詳細モーダルのセレクト） | `columns[]` | 未着手・完了は固定タブ（5.1）。 |
| グループ | 「グループ」 | `columns[].groups[]` | 列の中でカードを束ねる単位。プロジェクト名などに使う想定（5.2）。 |
| カード（タスク） | 「タスク」（ボタン文言は「タスクを追加」等） | `columns[].cards[]` | 本仕様書では「カード」で統一。 |
| 固定タブ | 列ヘッダーの 🔒 | `fixed: "start" \| "end"` | 削除・並び替え不可。名称変更・色分けは可能。 |
| Setting メニュー | 「Setting」 | `settings` オブジェクト | アプリ全体の設定を集約するプルダウンメニュー。歯車アイコンは v0.5 で廃止済み。 |
| 保存先 | 「保存先」 | `settings.savePath` | Electron版でのファイル書き込み先。Web版プロトタイプでは文字列を保持するのみ。 |

## 6. 主要機能一覧

### 6.1 タブ（列）管理

デフォルトのタブは「未着手 / 進行中 / 最終確認 / 完了」の 4 つ。このうち **未着手（先頭）と完了（末尾）は固定タブ**とし、削除・並び替えの対象外にする（列ヘッダーに 🔒 を表示）。ワークフローの入口と出口を固定することで、どのボードでも「まだ手をつけていないもの」と「終わったもの」が必ず同じ位置に来るようにする。それ以外のタブ（進行中・最終確認・ユーザーが追加したタブ）は自由に追加・削除・並び替えができる。

| 機能 | 内容 |
|---|---|
| タブの追加 | ボード右端の「＋ 新しいタブを追加」から作成。新規タブは常に固定タブ「完了」の直前に挿入される。 |
| タブの削除 | 列ヘッダーの × から削除。固定タブは削除不可。 |
| **タブ削除時のカードの行き先** | 削除しようとしたタブにカードが残っている場合、確認ダイアログに「削除すると N 件のカードは固定タブ『未着手』へ移動します」と明示する。OK した場合、カードは削除されず未着手タブの末尾へ移動し、`groupId` は `null`（未分類）にリセットされる（移動元のグループはタブ固有のため引き継げない）。固定タブ「未着手」が存在しない状態は起こり得ないため、この経路は常に成立する。 |
| タブの並び替え | 列ヘッダーをドラッグして並び替え（固定タブの前後には移動不可）。 |
| タブの名称変更 | 列名をダブルクリックしてインライン編集（固定タブも名称のみ変更可）。 |
| 件数バッジ | 列ヘッダーに、その列に属するカード数を表示。検索・フィルタが有効な間は `表示件数/全件数`（例: `3/12`）の形式に切り替わり、無効な間は全件数のみを表示する。ツールバー右の「全 N 件」はボード全体（フィルタ適用後）の合計。 |
| 空列表示 | カードが 0 件の列は `- empty -` を表示。 |
| タブの色分け | 列ヘッダー左の小さな丸ボタンから、タブの**上端の枠線だけ**に色を付けられる。タブ本体やヘッダーの背景は着色しない（あくまで一目で見分けるための線）。8色のプリセットから選ぶか、「枠線の色を解除」で既定の色に戻す。色は固定タブにも設定できる（固定はタブの位置・削除可否の話であり、色分けとは独立）。 |

### 6.2 タブ内グループ

- 同じタブの中に、プロジェクト単位などでまとめる**グループ**を作成できる。列下部の「＋ グループを追加」で作成し、グループ名はダブルクリックで変更可能。
- グループがまだ 1 つも無い列は従来どおりのフラットなカード一覧として表示され、グループを作った列だけがグループ見出し付きの区切り表示になる（既存の使い方を崩さない）。
- グループに属さないカードは「未分類」として同じ列内にまとめて表示される。
- カードのグループ所属は、詳細モーダルの「グループ」セレクト、またはカードをグループの一覧へドラッグ＆ドロップすることで変更できる。
- **ドラッグ＆ドロップの挙動**:
  - 別のタブから、移動先タブ内の**特定のグループ領域**（グループの展開されたカード一覧、または折りたたまれたグループの見出し）へ直接ドロップした場合は、そのグループの `groupId` を割り当てる。折りたたまれたグループの見出しにドロップした場合は、ドロップと同時にそのグループを自動的に展開する。
  - タブの背景（どのグループにも属さない領域）へドロップした場合のみ `groupId` を `null`（未分類）にリセットする。
  - 同一タブ内でカードからカードへドロップした場合は、ドロップ先カードと同じグループへ合流し、`settings.sortMode` が `"manual"` であればドロップ先の直前／直後（カードの上半分/下半分で判定）に挿入される。
- **グループの折りたたみ**: グループ見出し左の `▼ / ►` ボタンで折りたたみ・展開を切り替えられる。折りたたむとカード一覧と「＋タスクを追加」が非表示になり、見出しと件数バッジだけが残る。完了済みプロジェクトや優先度の低いグループでボードが縦長になるのを防ぐための機能。
  - 折りたたみ状態は `columns[].groups[].collapsed` ではなく **`settings.collapsedGroupIds`（グループ ID の配列）に保持する**。Undo/Redo はボードの内容（`columns`）だけをスナップショットする仕組みのため、折りたたみ状態を `columns` 側に置くと「タブを追加しただけなのに、以前に折りたたんだグループが Undo で開いてしまう」といった意図しない巻き戻りが起きる。表示設定と内容編集を型のレベルで分離することでこれを防ぐ（詳細は 6.15）。
- グループを削除すると、そのグループに属していたカードは削除されず「未分類」に戻る（確認ダイアログあり）。グループは列（タブ）をまたがない（列ごとに個別のグループ集合を持つ）。
- 6.13 の Setting メニューで機能自体をオフにできる。オフの間もデータ（`groups` / `groupId` / `collapsedGroupIds`）は保持され、再度オンにすれば元の状態で復元される。

### 6.3 タスクカード管理

| 機能 | 内容 |
|---|---|
| カードの追加 | 列下部の「＋ タスクを追加」、またはグループ内の「＋ タスクを追加」から作成。タイトルは必須、他は任意。新規作成時は優先度「低」・開始日「今日」を初期値とする（既存カードの編集時は保存済みの値をそのまま表示し、上書きしない）。 |
| カードの編集 | カードクリックで詳細モーダル（**画面中央に表示**）を開き、各項目を編集。Shift を押しながらのクリックは編集ではなく複数選択になる（6.10）。 |
| カードの削除 | モーダル内の「タスクを削除」から削除（確認あり）。 |
| **カードの複製** | 詳細モーダルの「複製」ボタン、または `Ctrl+D`（モーダルを開いた状態、またはカードを複数選択した状態）で複製できる。複製されたカードは新しい UUID を発行し、タイトル末尾に「のコピー」を付け、元のカードの直後（同一タブ・同一グループ）に挿入される。リンクも新しい UUID を発行し直す。`createdAt` / `updatedAt` は複製した時刻で新規に設定する。 |
| ステータス（タブ）の変更 | ドラッグ＆ドロップに加えて、詳細モーダルの「ステータス」セレクトからも変更できる。選択したステータスに応じて「グループ」セレクトの候補が切り替わる。 |
| カードの項目 | タイトル / ステータス（列） / グループ / 優先度 / 開始日 / 目標日 / 担当者（複数ユーザー対応時のみ） / タグ / メモ / リンク（複数可） |
| 優先度表示 | 色付きドットで表現（赤＝高、黄＝中、緑＝低）。6.13 の Setting メニューで機能自体をオフにでき、オフの間もカードの `priority` データは保持される。 |
| 更新日時 | カードの作成日時（`createdAt`）とは別に更新日時（`updatedAt`）を、保存・複製のたびに更新して保持する。並び順やフィルタには使わないが、将来の同期・競合解決の基礎情報として保持する（6.17、6.21）。 |

### 6.4 メモ（Markdown 対応）

- 詳細モーダルのメモ欄は「編集／プレビュー」タブ切り替え式。見出し（`#`〜`###`）・箇条書き（`- `）・タスクリスト（`- [ ]` / `- [x]`）・インラインコード（`` `code` ``）・強調（`**text**`）に対応した簡易 Markdown レンダラーでプレビューする。フル仕様の Markdown ではなく、あくまでメモを構造化しやすくするための限定サブセット。
- カード面には、Markdown 記法を除去したプレーンテキストとして 2 行までのプレビューを表示し、開かなくても内容を確認できるようにする。
- **チェックリスト進捗バッジ**: メモにタスクリスト（`- [ ]` / `- [x]`）が含まれる場合、カード面のメモプレビューの先頭に `☑ 2/5` のような進捗バッジを表示する（完了数/総数）。開かずに進捗を把握できるようにするための表示で、クリックしてチェックを切り替える操作はモーダルを開いた上での編集（テキストの書き換え）でのみ行う。
- レンダリング時のセキュリティ方針は 6.18 を参照。

### 6.5 リンク

- 詳細モーダルの「＋ リンクを追加」で 1 件ずつ追加。各リンクは `表示名（ラベル）` と `URL／ファイルパス` の組で管理し、ラベルは後から自由に変更できる。カード面にはラベル付きのチップとして表示され、クリックすると開く。
  - http/https は既定のブラウザで開く。
  - ローカルパスは Electron 版で OS の既定アプリ・File Explorer に委譲する（`shell.openPath`）。Web版プロトタイプでは実際には開けないため、その旨をトーストで案内する。
- **相対パス**: 各リンク行に「相対」チェックボックスを設置。オンにすると `settings.savePath`（保存先フォルダ）を基準にした相対パスとして扱う（例: `./assets/reference.pdf`）。NAS やクラウドストレージ経由で複数 PC から開く際のパス切れを避けるための指定で、カード面のリンクチップにも「相対」バッジを表示する。`settings.savePath` が未設定の間は、相対パスを解決する基準が無いため「相対」チェックボックスを無効化し、ツールチップで理由を示す。保存先が未設定のまま保存されたリンクは `isRelative` を強制的に `false` に落とす。
- リンクを開く際の検証方針は 6.18 を参照。

### 6.6 タグ・タグフィルタ

- カードに複数のタグを付けられる（詳細モーダルでチップ入力、`Enter` または `,` で確定）。カード面には `#タグ名` として表示。
- **正規化**: タグは前後の空白を除去し、同一カード内では大文字小文字を区別せずに重複を排除する。入力した文字列がボード内の既存タグと大文字小文字違いで一致する場合は、既存タグの表記（正規の表記）を採用し、表記ゆれの増殖を防ぐ。タグ名にカンマは使用できない（区切り文字として予約）。
- **サジェスト**: タグ入力欄はボード内に存在するタグを候補として表示する（ブラウザの `<datalist>` によるネイティブなオートコンプリート）。
- 検索フィルタの「タグ」セクションで、ボード内に実在するタグをチップとして一覧表示し、選択したタグのいずれかを含むカードだけに絞り込める（OR条件、6.7）。
- 6.13 の Setting メニューで機能自体をオフにできる。オフの間もカードの `tags` データは保持され、表示・入力欄が隠れるだけ。

### 6.7 検索・フィルタ

- 上部の検索ボックスで、**タイトル・メモ・タグ・リンクのラベル**を横断検索する（メモが Markdown で情報量を持つようになったため、タイトルだけでなく本文まで検索対象に含める）。
- 検索ボックスの右の「フィルター」から、優先度（複数選択）・目標日の範囲（開始/終了）・タグ（複数選択、ボード内に実在するタグのみ表示）で絞り込み。複数ユーザー対応がオンの場合のみ担当者フィルタも表示。優先度機能・タグ機能がオフの間は、それぞれのフィルタ項目も併せて隠れる。
- 有効なフィルタ数をボタン上のバッジで表示し、「クリア」で一括解除。
- **評価ロジック**: 検索ワード・優先度・目標日範囲・タグ・担当者の異種フィルタ間は **AND**（すべてを同時に満たすカードのみ表示）。優先度フィルタ内・タグフィルタ内はそれぞれ **OR**（選択した優先度／タグのいずれか 1 つでも該当すれば表示）。

### 6.8 並び順

- ツールバーの「並び順」で、列内のカード表示順を **作成日時順**（既定）と **手動並び替え** から選べる。この設定は `settings.sortMode` に保存され、Undo/Redo の対象外（アプリの表示設定のため。6.15）。
- 手動並び替え時のみ、カードをドラッグして列内の任意の位置に並べ替えられる（ドロップ先カードの上半分/下半分で前後どちらに入るかを判定）。作成日時順の間は並び替えの手動操作は無効。
- **検索・フィルタ適用中は、手動並び替え時であってもドラッグによる並び替えを一時的に無効化する**。画面上は非表示カードを挟んで隣接して見えるカード同士が、実際の配列順では隣接していないことがあり、ドラッグの結果が意図と異なる位置に保存されてしまうため。並び順セレクトの隣に理由を示す注記を表示する。タブ間・グループ間の移動（ステータス変更）は、この制限の対象外で常に可能。

### 6.9 日付選択（カレンダーUI）・日付の検証

- 開始日・目標日、フィルタの日付範囲はすべて、ネイティブの `<input type=date>` ではなく、テーマに合わせたカスタムのカレンダーポップオーバーで選択する。月送り・「今日」・「クリア」を備える。
- 両方設定されている場合、カードに「今日がどのあたりか」を示す進捗バーを表示する。目標日を過ぎても未完了（完了タブに入っていない）の場合は赤字で強調する。
- **日付の逆転**: 目標日が開始日より前の状態で保存しようとした場合、ブロックはせず「目標日が開始日より前になっています。このまま保存しますか？」と確認する。開始日・目標日の一方または両方が未設定、または目標日が開始日以降の場合は進捗バーを表示し、それ以外（逆転している場合）は進捗バーを表示しない。

### 6.10 複数選択・一括操作

- カードを Shift を押しながらクリックすると、詳細モーダルを開かずに複数選択できる（トグル式）。`Ctrl+A`（フォーカスが入力欄に無く、詳細モーダルも閉じている場合）でボード上の全カードを選択できる（6.16）。
- 1 件以上選択すると画面下部に一括操作バーが表示される。バーには「選択した件数」「移動先タブの選択」「一括操作▾（下表）」「削除」「選択解除」を配置する。
- 通常クリック（Shift なし）は、選択の有無にかかわらず常にそのカードの詳細モーダルを開く。
- 選択の解除は、カード以外の「何もないところ」（ボードの余白・列の背景など）をクリックしたときに行う。誤って別カードをクリックしても詳細が開くだけで選択状態を壊さない一方、明確に空所をクリックすれば一括解除できる。
- 「一括操作」ボタンを押すと、一括操作バーの上にポップオーバーが開き、以下の操作ができる。ステータス移動・削除の実行後は選択解除されるが、それ以外の操作は実行後も選択状態を維持し、続けて別の一括操作を行える。

  | 操作項目 | 動作内容 |
  |---|---|
  | 一括ステータス移動 | 選択したすべてのカードを指定した列へ移動（実行後は選択解除、`groupId` は未分類にリセット）。 |
  | 一括優先度変更 | 選択カードの優先度（高／中／低）を一括更新。優先度機能がオフの間はこの項目自体を隠す。 |
  | 一括グループ変更 | 選択カードが**すべて同一タブ内**にある場合のみ、所属グループを一括指定できる。複数タブにまたがって選択している場合はセレクトを無効化し、理由を注記する。グループ機能がオフの間はこの項目自体を隠す。 |
  | 一括担当者変更 | 複数ユーザー対応がオンの場合のみ表示。入力した担当者名を選択カード全体に設定する。 |
  | 一括目標日設定 | カレンダーポップオーバーで選んだ日付を選択カード全体の目標日に設定する。「クリア」で目標日を一括解除できる。 |
  | 一括タグ付与 | テキスト入力に入力して Enter で、選択カード全員に共通のタグを追加（6.6 の正規化ルールを適用）。タグ機能がオフの間はこの項目自体を隠す。 |
  | 一括タグ削除 | 選択カードが持つタグの一覧をチップで表示し、クリックでそのタグを選択カード全体から削除。 |
  | 一括削除 | 確認ダイアログを表示のうえ、選択カードを一括削除。 |

### 6.11 File メニュー・データ保存

- 画面左上の「File」メニューに、JSON のエクスポート／インポート、サンプルデータへのリセットを集約する（ヘッダー上には常設ボタンを置かない）。
- 保存先パスの指定は 6.13 の Setting メニューに統合されている（Electron 版ではネイティブのフォルダ選択ダイアログを想定。Web版プロトタイプではパス文字列の保持のみで、実際のファイル書き込みは行わない）。
- エクスポートで現在のボード状態（タブ構成・カード・設定）を JSON 出力し、インポートで復元できる。
- **インポート時の検証**: 読み込んだ JSON のルートがオブジェクトであること、`columns` が配列であること、各列に `id` と `name` が存在することを検証し、いずれかを満たさない場合はインポートを中断してエラー内容を表示する（形式が不明のまま起動不能になることを避ける）。
- **インポート時の自動修復**: カードの `groupId` が、その列に実在しないグループを指している場合は自動的に `null`（未分類）へ修復し、修復件数をトーストで案内する。
- **インポート前の自動バックアップ**: インポートを実行する直前の状態を、通常のバックアップ世代（6.17）とは別に保持する。誤って想定外の JSON を読み込んだ場合に、直前の状態へ戻れるようにするため。
- インポート・サンプルデータへのリセットを行うと、6.15 の Undo／Redo 履歴はクリアされる（読み込んだデータより前の状態には戻せない。インポート前バックアップは別に保持されているため、データそのものは失われない）。
- **将来検討（v1.0 に向けて）**: 現状は 1 ファイル 1 ボードで、ファイルの切り替えは「インポート（＝現在のボードを置き換える）」でしか行えない。`shot_tracker` のサーバーパス切り替えに相当する「開く…」「名前を付けて保存…」「最近使ったファイル」を File メニューに追加することを、Electron 実装フェーズの優先課題とする（6.19）。

### 6.12 複数ユーザー対応・表示名（拡張性のための設定）

- 表示名（自分の名前）は 6.13 の Setting メニューからいつでも変更できる。複数ユーザー対応のオン/オフに関わらず常に編集可能。
- 現状は個人利用が前提だが、将来チームで使うことを見込み、Setting メニューに **複数ユーザー対応を有効にする** チェックボックスを設ける。
- **デフォルトはオフ**。オフの間は担当者の入力欄・カード上の担当者表示・検索の担当者フィルタ・一括操作の担当者変更・タイトルバーのユーザー表示をすべて非表示にし、個人のタスク管理に画面をシンプルに保つ（表示名自体は裏で保持され続ける）。
- オンにすると、タイトルバーのユーザー表示・カードへの担当者アサイン・担当者フィルタ・一括担当者変更が有効になる。メンバー管理や権限などのチーム機能そのものは引き続き将来検討（6.19）。

### 6.13 Setting メニュー（アプリ全体の設定を集約）

タイトルバーの **File の左隣**に、独立した「Setting」メニュー（プルダウン）を置く。歯車アイコンの「設定」モーダルは v0.5 で廃止済みで、アプリ全体に関わる設定はすべてこの Setting メニュー1か所に集約する。

| セクション | 項目 | 内容 |
|---|---|---|
| 表示 | 優先度機能を有効にする | チェックボックス。オフにするとカードの優先度ドット・優先度の入力欄・優先度フィルタ・一括優先度変更が隠れる。既定はオン。 |
| 表示 | グループ機能を有効にする | チェックボックス。オフにするとタブ内グループ（6.2）の UI が隠れ、列はすべてフラットなカード一覧になる。既定はオン。 |
| 表示 | タグ機能を有効にする | チェックボックス。オフにするとタグ入力・カード上のタグ表示・タグフィルタ・一括タグ操作が隠れる。既定はオン。 |
| Theme | Black / White | テキストのみの 2 択ボタン（アイコンなし）。クリックした時点で即座に切り替わる。既定は Black（ダーク）。 |
| ユーザー | 表示名 | テキスト入力。自分の名前をいつでも変更できる（6.12）。 |
| ユーザー | 複数ユーザー対応を有効にする | チェックボックス（6.12）。 |
| 保存先 | 保存先パス + 参照... | テキスト入力とフォルダ選択（Electron版でネイティブダイアログを想定）。初回起動時は既定パスをあらかじめ設定し、未設定状態を作らない（6.17）。 |

いずれの項目も操作した時点で即時反映・即時保存され、メニュー自体はチェックや入力のたびに閉じない（外側クリックで閉じる）。

### 6.14 テーマ（ライト／ダーク）

- アクセントカラー（アンバー）・タイポグラフィ・レイアウトはそのままに、背景・境界線・文字色・影の濃さだけをライト用トークンに差し替える。単純な白黒反転ではなく、ダーク側と同じ「面が奥から手前に向かって明るくなる」階調構造（ページ < パネル < カード < チップ）をライト側でも保つ。
- 優先度ドットやリンクの色（成功・警告・危険・リンク）は、白背景でも視認できるようライト用に個別調整する。
- テーマ設定は `settings.theme` に保存され、次回起動時も維持される。Undo/Redo の対象外（6.15）。

### 6.15 Edit メニュー（Undo / Redo）

タイトルバーの **File の左隣・Setting の右隣**に「Edit」メニューを置く。

| 項目 | ショートカット | 内容 |
|---|---|---|
| 元に戻す（Undo） | `Ctrl+Z` | 直前のボード編集を1手戻す。 |
| やり直す（Redo） | `Ctrl+Shift+Z` | Undo で戻した操作をやり直す。新しい編集を行うと Redo 履歴は破棄される。 |

- **対象範囲**: Undo/Redo は `columns`（タブ・グループ・カードの追加/編集/削除/移動・並び替え・複製）のみをスナップショットの対象とする。以下は明示的に対象外とし、それぞれ独自の仕組みで保持する。
  - グループの折りたたみ状態（`settings.collapsedGroupIds`、6.2）
  - 並び順モード（`settings.sortMode`、6.8）
  - Theme・優先度/グループ/タグ機能の有効・無効・複数ユーザー対応・表示名・保存先といった `settings` 配下の設定全般（6.13）
  - これらを対象外にする理由は、内容の編集とは異なる「表示・アプリの好み」を Undo で不意に巻き戻さないため（6.2 で発覚した設計上の教訓）。
- **粒度**: テキスト系の項目（タイトル・メモ・グループ名・タブ名など）は、1 文字ごとではなく **入力の確定単位**（詳細モーダルの保存、インライン編集の blur/Enter）で 1 手として記録する。ドラッグ移動・追加・削除・一括操作は操作 1 回で 1 手（一括操作は選択カード全体をまとめて 1 手）。
- 履歴の上限は **50 手**。ボードのディープコピーをスタックに積む方式のため、上限を設けてメモリ使用量を抑える。
- 戻せる操作が無い場合は Undo、やり直せる操作が無い場合は Redo が淡色表示（無効化）になる。
- JSON インポートやサンプルデータへのリセットを行うと履歴はクリアされる（6.11）。

### 6.16 キーボードショートカット

マウス操作を減らし、高速な操作を可能にするための標準ショートカットを整備する。

| ショートカット | 動作 |
|---|---|
| `Ctrl+Z` / `Ctrl+Shift+Z` | Undo / Redo（6.15） |
| `Ctrl+F` | 検索ボックスへフォーカス |
| `Ctrl+N` | **最後に操作したタブ**（カードを開いた・追加したタブ）に新規タスク作成モーダルを開く。まだ何も操作していないセッションでは先頭のタブを対象にする。 |
| `Ctrl+S` | デバウンスを待たず即時保存を実行し、「即時保存しました」とトーストで案内する（6.17）。 |
| `Ctrl+Enter` | 詳細モーダルを開いている間、保存して閉じる。 |
| `Ctrl+D` | 詳細モーダルを開いている間はそのカードを、モーダルを開いていない場合は選択中のカードすべてを複製する（6.3）。 |
| `Ctrl+A` | フォーカスが入力欄に無く、詳細モーダルも閉じている場合、ボード上の全カードを選択する（6.10）。 |
| `Esc` | 開いているものを、カレンダーポップオーバー › タブ色ポップオーバー › 詳細モーダル › 複数選択、の優先順位で 1 段階だけ閉じる／解除する（詳細モーダルの中でカレンダーだけを開いている場合、`Esc` はカレンダーだけを閉じ、モーダルは開いたままにする）。 |
| `Delete` / `Backspace` | カードを複数選択中に、フォーカスが `input` / `textarea` / `select` / 編集可能領域に無い状態であれば、確認ダイアログ付きで一括削除を実行する。 |

- `Ctrl+F` はブラウザ標準の「ページ内検索」と衝突するため、Web版プロトタイプでは確実に奪えない場合がある（ブラウザ側の実装依存）。Electron 版ではアプリ側でショートカットを掌握できるため、意図通り検索ボックスへフォーカスする。
- キーボードだけでの列内の並び替えや、Shift+クリック以外での複数選択（例: `Space` でのトグル）は本バージョンでは未対応。将来検討とする（優先度は低）。

### 6.17 データ整合性・自動保存

将来の複数PC・複数人での利用や、予期しないアプリ終了に備えて、以下のデータ保護策を導入する。

| 項目 | 内容 |
|---|---|
| `schemaVersion` | ルート直下にデータのスキーマバージョンを **単調増加の整数**（例: `1`）で保持する。文字列（`"0.9"` 等）は将来 `"0.10"` のようなバージョンが来たときに辞書順比較で破綻するため採用しない。マイグレーションは `1 → 2 → 3 …` と関数を連鎖適用する形にし、飛び越しアップグレードにも耐えられるようにする。アプリの表示バージョン（v0.10 等）とは独立の値。 |
| ID の UUID(v4) 化 | すべての `id`（タブ・カード・グループ・リンク）を UUID v4 で発行する（`crypto.randomUUID()`、非対応環境ではフォールバック実装）。JSON の手動インポートやカードの複製、将来のマルチユーザー同期時の ID 衝突を避ける。 |
| 自動保存（デバウンス） | カードの追加・編集・移動などの変更を検知後、**500ms** 操作が止まってからまとめて保存する（連続編集中に保存が頻発しないようにするため）。保存中はツールバーに「保存中…」、完了後は「保存済み」と表示する。`Ctrl+S`（6.16）でデバウンスを待たず即時保存できる。 |
| **保存の原子性（Electron 実装時）** | ローカル JSON ファイルへの書き込みは、`保存先.tmp` に書き切ってから `rename` で本体に置き換える（アトミックリネーム）。書き込み中にアプリが強制終了しても、本体ファイルは「直前の完全な状態」か「新しい完全な状態」のどちらかにしかならず、末尾が欠けた壊れた JSON が生成されることを構造的に防ぐ。 |
| バックアップ世代管理 | 保存のたびに直前の内容を退避するが、世代を**時間軸で分ける**。500ms デバウンスのたびに全世代をローテーションすると、連続編集数回で全世代が「ほぼ同じ最新状態」になってしまい、バックアップの目的（データ消失への備え）を果たせないため。 |

  バックアップの世代設計:

  | 世代 | 内容 | 更新条件 |
  |---|---|---|
  | `.bak1` | 直前の保存内容 | 保存のたびに更新 |
  | `.bak2` | 10 分以上前の状態 | 前回の `.bak2` 更新から 10 分以上経過した保存で更新 |
  | `.bak3` | このセッションを開始した時点の状態 | アプリ起動（ページ読み込み）時に 1 回だけ書き込み |

  Web版プロトタイプでは `localStorage` 上のキー（`..._bak1` 〜 `_bak3`、`_bak2_at` に世代更新時刻）でこれを再現する。Electron 版では `settings.savePath` 配下のファイルとして実装する。

- Undo／Redo（6.15）とは独立した仕組み。Undo/Redo は「操作の巻き戻し」、自動保存・バックアップは「データ消失への備え」という異なる目的を持つ。
- **多重編集・競合の検出（将来検討）**: 同じ JSON ファイルを NAS やクラウドストレージ経由で複数 PC から開く運用を想定しているが、v0.10 では同時編集時の競合検出・マージは行わない。v1.0 に向けて、(1) 読み込み時にファイルの更新日時を控えておき、保存直前に変化していれば警告する、(2) 起動時にロックファイルを作成し、既存ロックがあれば読み取り専用で開く、の 2 案を軽い順に検討する。`cards[].updatedAt`（6.3）は将来の競合解決の基礎情報として現時点から保持している。

### 6.18 セキュリティ

| 項目 | 方針 |
|---|---|
| Markdown レンダリングの XSS 対策 | 簡易 Markdown レンダラー（6.4）は、タグを組み立てる前に必ずユーザー入力を HTML エスケープしてから、限定された固定のタグ（見出し・リスト・`<code>` など）で囲む。ユーザー入力がそのまま HTML タグとして解釈される経路を作らない。JSON インポート（6.11）は外部データの流入口であるため、同じレンダラーを通る限りこの対策が及ぶ。 |
| リンクを開く際の検証（Electron 実装時） | `shell.openExternal` は `http` / `https` のみを許可するスキーム allowlist を設ける（`file:` やカスタムスキーム経由での意図しない起動を防ぐ）。相対パス（6.5）は `path.resolve(savePath, url)` の結果が `savePath` 配下にあることを検証してから `shell.openPath` を呼び、`../` によるディレクトリトラバーサルを防ぐ。`.exe` / `.bat` / `.lnk` など実行可能拡張子は確認ダイアログを挟む。 |
| Electron のプロセス構成（実装方針） | `contextIsolation: true` / `nodeIntegration: false` / `sandbox: true` を既定とし、レンダラープロセスから直接 `fs` や `shell` を呼び出さない。ファイル I/O・保存・バックアップローテーション・リンクを開く処理はすべてメインプロセス側の IPC ハンドラに寄せ、レンダラーは preload 経由でその API のみを呼び出す。 |

### 6.21 完了タブのアーカイブ（将来検討）

- 固定タブ「完了」は増える一方で、減らす仕組みが現状無い。長期運用すると完了タブだけが数百件規模になり、スクロールやファイルサイズが膨らむおそれがある（9. 非機能要件）。
- 対応案（軽い順）: (a) 完了タブに「N 日より前を非表示」トグルを設ける、(b) 「アーカイブへ移動」で別ファイル（例: `archive_YYYYMM.json`）へ書き出す、(c) 完了タブは既定で最新 50 件のみ表示し「さらに表示」で追加読み込みする。まずは (a) の実装コストが低い。v1.0 に向けた検討課題とする。

- `shot_tracker` のダークテーマ・密度の高いカード表示を踏襲しつつ、列数・列名（固定タブを除く）は完全にユーザー定義。
- ブランドマーク（旧: プレーンな `//`）は、アクセントカラーのグラデーションを効かせた小さな斜線ロゴ。タイムコード／スラッシュ表記のモチーフを残しつつ質感を上げる。
- ヘッダーには常時表示のバッジ（旧「ローカル保存」表示）は置かない。ユーザー表示は複数ユーザー対応がオンの時だけ右端に出る。
- タイトルバーは2段構成。上段にメニューバー（Setting / Edit / File とユーザー表示）、下段にソフト名（ブランド）を配置する。
- カードにはタイトル・優先度・タグ・メモのプレビュー（チェックリストがあれば進捗バッジ付き）・開始日/目標日・リンクチップを表示し、詳細はクリックで画面中央のモーダルとして展開（Shift+クリックは複数選択、選択解除は空所クリック）。
- 列内にグループを作ると、列の中に「プロジェクトA」「未分類」のような区切りが表示される（6.2）。
- 「Setting」メニューで各機能のオン/オフ、Theme（Black/White）、表示名、複数ユーザー対応、保存先をすべて設定できる（6.13）。
- 「Edit」メニューで Undo（Ctrl+Z）／Redo（Ctrl+Shift+Z）ができる（6.15）。
- ツールバー右側に「保存中…／保存済み」の自動保存インジケーターを表示する（6.17）。
- グループ見出しの `▼/►` で折りたたみができ、折りたたんだグループは件数バッジのみ表示される（6.2）。

```jsonc
{
  "schemaVersion": 1,              // 整数。マイグレーション判定に使用（6.17）
  "settings": {
    "multiUser": false,
    "currentUser": "泉谷",
    "savePath": "Z:/Users/ku_kageya/task_tracker/board.json",
    "sortMode": "created",
    "priorityEnabled": true,
    "groupsEnabled": true,
    "tagsEnabled": true,
    "theme": "dark",
    "collapsedGroupIds": []        // 折りたたみ中のグループ ID（6.2）。Undo/Redo 対象外
  },
  "columns": [
    {
      "id": "c1b2a3d4-e5f6-4890-abcd-1234567890ab",
      "name": "進行中",
      "fixed": null,
      "color": "#3b82f6",
      "groups": [
        { "id": "g9f8e7d6-c5b4-4210-fedc-0987654321ba", "name": "プロジェクトA" }
      ],
      "cards": [
        {
          "id": "a1b2c3d4-e5f6-4890-1234-56789abcdef0",
          "title": "仕様書のレビュー",
          "assignee": "泉谷",
          "priority": "high",
          "startDate": "2026-08-01",
          "dueDate": "2026-08-05",
          "tags": ["ドキュメント", "急ぎ"],
          "memo": "### 確認項目\n- [x] 構成案の確認\n- [ ] 承認依頼の発行",
          "links": [
            { "id": "l1a2b3c4-d5e6-4890-1234-567890abcdef", "label": "素材フォルダ", "url": "./assets/spec_v001.docx", "isRelative": true }
          ],
          "groupId": "g9f8e7d6-c5b4-4210-fedc-0987654321ba",
          "createdAt": "2026-08-01T09:00:00+09:00",
          "updatedAt": "2026-08-02T19:30:00+09:00"
        }
      ]
    }
  ]

```

**フィールド一覧**（`?` は任意、既定値は「未指定時にアプリが補う値」）

| フィールド | 型 | 必須/任意 | 既定値 | 説明 |
|---|---|---|---|---|
| `schemaVersion` | integer | 必須 | — | ルート直下。6.17。 |
| `settings.*` | object | 必須 | — | 欠けているキーは読み込み時に既定値で補完する（マイグレーション、6.17）。 |
| `settings.savePath` | string | 任意 | 初回起動時の既定パス | 空文字のままにはしない（6.5, 6.13）。 |
| `settings.collapsedGroupIds` | string[] | 任意 | `[]` | 6.2。 |
| `columns[].id` / `.name` | string | 必須 | — | インポート検証で必須チェックする 2 項目（6.11）。 |
| `columns[].fixed` | `"start"` \| `"end"` \| `null` | 任意 | `null` | 未着手・完了を先頭・末尾に固定（6.1）。中間タブはすべて `null`。**配列内の並び順そのものが表示順**（`order` フィールドは廃止。旧バージョンからの読み込み時のみ、存在すれば 1 度だけ参照して配列順に変換し、以後は破棄する）。 |
| `columns[].color` | string(hex) \| `null` | 任意 | `null` | 8色プリセットのいずれか（6.1）。 |
| `columns[].groups[].id` / `.name` | string | 必須 | — | 6.2。`order` は持たず配列順が正。 |
| `cards[].groupId` | string \| `null` | 任意 | `null` | 存在しないグループ ID を指す場合はインポート時に `null` へ自動修復（6.11）。 |
| `cards[].tags` | string[] | 任意 | `[]` | 6.6 の正規化ルールを適用済みの状態で保持。 |
| `cards[].links[].isRelative` | boolean | 任意 | `false` | 6.5。 |
| `cards[].createdAt` / `.updatedAt` | ISO 8601 string | 必須 | 保存時刻 | 6.3。 |

- 1 ファイル 1 ボードを基本とし、複数プロジェクトは複数ファイルで管理する（`shot_tracker` のサーバーパス切り替えに相当）。保存先は `settings.savePath` で指定する。将来的な「開く」「最近使ったファイル」は 6.11 参照。
- `id` はすべて UUID v4。手動 JSON 編集やインポート、将来の同期における衝突を避ける（6.17）。
- `columns[].groups` は列（タブ）ごとに独立して持つ。カードの `groupId` はその列の `groups[].id` を参照し、列をまたいで移動した場合は `null`（未分類）にリセットする。
- `settings.sortMode` が `"manual"` の間は、`cards` 配列内の並び順そのものが表示順として扱われる（ドラッグ操作は配列の並び替えとして永続化される）。`"created"` のときは表示時に `createdAt` でソートし、配列順は変更しない。
- 将来的に複数ボードをタブで切り替えられるようにする拡張余地を残す。

## 9. 技術スタック（案）

| レイヤー | 候補 |
|---|---|
| ランタイム | Electron（`contextIsolation: true` / `nodeIntegration: false` / `sandbox: true`、preload 経由の IPC。6.18） |
| UI | HTML/CSS + Vanilla JS、または React（規模次第で判断） |
| データ永続化 | ローカル JSON ファイル（`fs` 経由、メインプロセスの IPC ハンドラに集約）。アトミックリネームで書き込む（6.17）。将来的に SQLite も検討 |
| ドラッグ＆ドロップ | HTML5 Drag and Drop API、または `SortableJS` |

v0.1 のプロトタイプでは依存を増やさず、Vanilla JS + localStorage で UI 検証を行う（本リポジトリの `prototype/index.html` を参照）。

## 10. 非機能要件

- オフラインで完結すること（外部サーバー通信は必須にしない）。
- カード枚数が数百件になっても列のスクロールが破綻しないこと。完了タブが際限なく増え続ける問題への対応は 6.21（アーカイブ）を参照。
- ダークテーマを既定とする（`shot_tracker` の視認性の高さを踏襲）。
- 編集操作から保存までは 500ms のデバウンスを挟み、時間軸で分けた 3 世代のバックアップを保持すること（6.17）。予期しないアプリ終了があっても、直前の保存世代までは復元できること。保存はアトミックリネームで行い、書き込み途中の破損ファイルが生成されないこと。
- データファイルは整数の `schemaVersion` を持ち、将来の構造変更に対して自動マイグレーションできる設計とすること（6.17）。
- Markdown レンダリングとリンクを開く処理は、6.18 のセキュリティ方針に従うこと。

## 11. Web版プロトタイプの制約一覧

`prototype/index.html` はブラウザ上で動作する検証用実装であり、以下はいずれも Electron 版で解消される想定の制約。個別の節で述べている内容をここに集約する。

| 制約（Web版プロトタイプ） | Electron 版での解決 |
|---|---|
| リンク先のローカルファイルを実際には開けない（トーストで案内するのみ） | `shell.openPath`（絶対パス）／`savePath` を基準に解決してから `shell.openPath`（相対パス）。6.5, 6.18 |
| `Ctrl+F` がブラウザ標準の「ページ内検索」と競合しうる | アプリがショートカットを掌握し、確実に検索ボックスへフォーカスする。6.16 |
| 保存先（`settings.savePath`）はパス文字列を保持するのみで、実際のファイル書き込みは行わない | `fs` 経由でメインプロセスが実書き込みを行う。6.17 |
| バックアップ世代（`.bak1`〜`.bak3`）は `localStorage` のキーとして再現している | 保存先フォルダ配下の実ファイルとして保持する。6.17 |
| 「参照...」ボタン（保存先フォルダ選択）は実際には何も開かず、案内のトーストを出すのみ | ネイティブのフォルダ選択ダイアログを開く。6.13 |
| 1 ファイル 1 ボードで、複数ファイルの切り替え導線が無い（インポートは「置き換え」） | File メニューに「開く」「名前を付けて保存」「最近使ったファイル」を追加する。6.11 |
| 保存の原子性（アトミックリネーム）・多重編集の検出は実装されていない（`localStorage` の性質上、単一ファイルの破損や複数プロセスからの競合が起こらないため） | ファイル I/O 実装時にアトミックリネームと更新日時ベースの競合検出を実装する。6.17 |

## 12. 受け入れ基準（抜粋）

「プロトタイプ検証・要件確定」の判定材料として、今回のレビューで新たに定義した挙動を中心に Given/When/Then 形式で記載する。実装・検証時のチェックリストとして使う。

1. **タブ削除でカードが未着手へ移動する**: 進行中タブに 3 枚のカードがある状態で、タブの × を押す → 確認ダイアログに「3 件のタスクがあります。削除すると…未着手へ移動します」と表示される → OK → 3 枚は「未着手」の末尾に移動し `groupId` は `null`、`Ctrl+Z` で元の列・グループに復元される。
2. **Undo はグループの折りたたみを巻き戻さない**: グループを折りたたんだ状態でカードを 1 枚追加する → `Ctrl+Z` → カードの追加は取り消されるが、グループは折りたたまれたまま。
3. **フィルタ中は手動並び替えのドラッグが効かない**: 並び順を「手動並び替え」にし、検索で絞り込んだ状態でカードをドラッグする → 並び順セレクトの隣に注記が表示され、ドロップしても配列順は変化しない。
4. **別タブの特定グループへ直接ドロップできる**: A タブのカードを B タブの「プロジェクトX」グループの領域へドラッグ＆ドロップする → カードは B タブへ移動し、`groupId` は「プロジェクトX」の ID になる。
5. **折りたたみ済みグループへドロップすると自動展開する**: 折りたたまれたグループの見出しにカードをドロップする → グループが展開され、カードがそのグループの末尾に入る。
6. **優先度・タグフィルタは OR、異種フィルタ間は AND**: 優先度「高」「中」とタグ「急ぎ」を選択する → 「（優先度が高または中）かつ（タグに急ぎを含む）」カードだけが表示される。
7. **目標日が開始日より前だと警告が出る**: 開始日を 8/20、目標日を 8/10 にして保存する → 「目標日が開始日より前になっています」の確認が出て、キャンセルすると保存されない。
8. **不正な JSON のインポートは拒否される**: `columns` を含まない JSON をインポートする → エラー内容（例: `columns 配列がありません`）を伴って拒否され、現在のボードは変化しない。
9. **孤立した `groupId` 参照は自動修復される**: 存在しないグループ ID を持つカードを含む JSON をインポートする → インポートは成功し、該当カードは未分類になり、修復件数がトーストで案内される。
10. **バックアップ 3 世代が時間軸で分散する**: 数秒おきに 5 回連続で保存が発生する状況で `.bak1` は毎回更新されるが、`.bak2` は直近の更新から 10 分経過するまで更新されない。
11. **Undo 直後の Redo で元に戻る**: カードを削除して `Ctrl+Z` で復元し、続けて `Ctrl+Shift+Z` を押す → 削除した状態に戻る。
12. **一括グループ変更は同一タブ内のみ有効**: 異なるタブのカードを同時に選択した状態で一括操作を開く → グループ変更のセレクトが無効化され、理由が表示される。
13. **カードの複製で ID が新規発行される**: カードを複製する → 複製後のカードは元のカードと異なる `id` を持ち、`title` の末尾に「のコピー」が付き、元カードの直後に並ぶ。
14. **検索がメモ・タグ・リンクラベルにもヒットする**: タイトルには含まれないが、メモにだけ含まれるキーワードで検索する → 該当カードが表示される。
15. **タグの大文字小文字違いが重複登録されない**: 既存タグ「UI」があるカードに、詳細モーダルで「ui」と入力してタグを追加する → 追加されるのは「UI」（既存の表記）で、「ui」という別タグは作られない。
